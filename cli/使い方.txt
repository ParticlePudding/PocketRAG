RAG プロンプトビルダー CLI（rag.exe）

資料を検索して、社内ChatGPTなどに貼り付けるプロンプトを作るコマンドです。
処理はすべてこのPCの中で行い、外部とは通信しません（「models download」を除く）。
Node.js などのインストールは不要です。
rag.exe と同じ場所の engine フォルダ（ネイティブ版エンジン）を使って高速にベクトル化します。
フォルダの中身は、すべて同じ場所に置いたまま使ってください。

■ はじめに
このフォルダで PowerShell を開いて実行します。
  開き方：エクスプローラーでこのフォルダを開き、上のアドレス欄に powershell と入力して Enter を押す。
  次のコマンドで、使えるコマンドの一覧を表示します（先頭の .\ も入力します）。
  .\rag.exe help
  ※ 説明の中の「rag ○○」は、PowerShell では「.\rag.exe ○○」と入力してください。

■ 読み込める資料
PDF、Word（.docx）、Excel（.xlsx）、PowerPoint（.pptx）、テキスト、Markdown、CSV、HTML など。
表はタブ区切りの行として読み取ります（データシートのスペック表など）。スキャンした画像だけの PDF は読めません。
Excel は空のセルを空欄のまま残し、日付・％・通貨などは画面の表示どおりにします。長い表を分けるときは、分けた後ろの部分にも列名の行を付けます。
どう読み取られたかは  .\rag.exe text 資料.pdf  で確認できます。

■ 基本の流れ
1. 資料をインデックス化（最初と、資料を更新したときに1回）
     .\rag.exe index .\テスト用資料
   → rag-index.json ができます。models フォルダに埋め込みモデルがあればハイブリッド検索になります
2. 検索結果を確認（任意）
     .\rag.exe search "日本で一番大きい湖は？"
3. プロンプトを作ってクリップボードにコピー → 社内ChatGPTに貼り付け
     .\rag.exe prompt "屋久島と富士山は、それぞれ何年に、どの区分で世界遺産に登録されましたか？" -c
   ファイルに保存するときは  -o prompt.txt 、API用のJSONは  --json

■ ローカルLLM（LM Studio など）を使うとき（任意）
  .\rag.exe ask "琵琶湖の面積は？" --llm http://localhost:1234/v1
  .\rag.exe eval testset.json --llm http://localhost:1234/v1 --csv 結果.csv
  ※ eval は --llm を付けなければ検索の当たり率だけを測ります

■ 主なオプション
  -k 5              プロンプトに入れる資料の件数
  -f qa|summary|extract|compare   回答の形式（質問に答える／要約／抜き出し／表）
  --instr "300字以内で"   回答の形式に追加する指示
  -m ruri-v3-30m    使う埋め込みモデル（index のとき）。ruri-v3-30m / bge-m3 / embeddinggemma-2
  --keyword         意味検索を使わずキーワード検索だけにする
  --base-file 基本.txt / --extra-file 追加.txt / --no-extra   プロンプトのルールを差し替える
  rag.config.json   よく使う設定を書いておくファイル（同じフォルダかカレントフォルダ）

■ 画面で使う
  .\rag.exe app
  → プロンプトビルダーがウィンドウで開きます（ベクトル化はネイティブ版で高速）。終了はコマンドの画面を閉じる

■ 速さの調整
  --threads 4       CPU のスレッド数（既定は自動）
  --device dml      Windows の GPU（DirectML）で計算（環境によっては CPU の方が速いこともあります）

■ テスト用資料
  テスト用資料\                 Wikipedia の記事 6 件（testset.json で評価）
  テスト用資料（技術文書）\     架空のセンサ基板のデータシート・設計書・BOM など 13 件（testset-tech.json で評価）
    .\rag.exe eval testset-tech.json -m embeddinggemma-2

■ 続けて質問する（速い）
  .\rag.exe shell
  → 質問を入力して Enter を押すたびに、プロンプトを作ってクリップボードにコピーします。モデルを読み込んだままなので2問目から速く動きます。
    /s 質問 で検索結果だけを表示、/k 3 で資料の件数を変更、/q で終わります。

■ 資料の一部を外す・偏りを減らす
  --exclude "旧版/**,*_old.*"   index のときに、旧版のフォルダや古いファイルを読み込まない（カンマで区切って複数指定）
  --per-doc 2                  search・prompt のときに、1つの資料から入れるかたまりを2件までにする（問い合わせ履歴のような大きな資料が上位を占めるとき）

■ うまく見つからないとき
・型番・品番・エラーコードはそのまま書く（H-21 と H21、全角と半角は同じものとして探します）。
・英語の資料が多いときは、英語に強いモデルを使う：-m embeddinggemma-2（または bge-m3）。日本語だけなら ruri-v3-30m が速くて十分です。
・資料の言葉で書き足す：--extra "password recovery" のように、資料に出てくる言葉（英語の用語など）を足すと当たりやすくなります。
・資料の読み取りを確認する：.\rag.exe text 資料.pdf で、表や段組みが正しく読めているかを見られます。
・古い版の資料が混ざるとき：出典に「版」「日付」が出ます。新しい資料だけを index するのが確実です。

■ ブラウザ版との関係
検索・プロンプト生成の仕組みはブラウザ版（rag-prompt-builder.html）と同じものです。
同じ資料・同じ設定なら、同じプロンプトができます。

■ 注意
・engine フォルダが無い・読めないときは、内蔵の WASM 版（遅い）で動きます。rag.exe models で確認できます。
・署名のない exe なので、初回に SmartScreen の警告が出ることがあります。社内のルールに従って使ってください。
・コマンドプロンプトで日本語が化けるときは、結果を -o でファイルに保存するか -c でコピーしてください。
